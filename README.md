# SmartPlant

AI + IoT + Maintenance + Operations platform. Production architecture (backend owns
business logic, database is the source of truth, RBAC everywhere) with a zero-dependency
demo deployment.

## Quick start

```bash
python3 run.py
```

`run.py` does everything on first launch:

1. Checks prerequisites (Node.js ≥ 22, npm, Python 3).
2. Creates `.env` from `.env.example` (edit it to add AI keys).
3. Installs backend dependencies (`npm install`).
4. Syncs the frontend into `frontend/dist` (served by the API).
5. Starts the API + frontend on http://localhost:4000.
6. Opens the application in your browser (Ctrl+C stops it).

Options: `--port 8080`, `--skip-install`, `--no-browser`.

## Features

| Area | What works |
|---|---|
| **Dashboard** | Live KPIs, energy/temperature charts, fleet table, active alerts, upcoming tasks |
| **Machines** | Search/filter, health bars, detail view with 24h temp/power/load charts, risk report, alert & maintenance history, compatible parts, documents |
| **Telemetry** | Live latest readings + IoT ingestion form (dedupe, validation, thresholds → alerts) |
| **Alerts** | Filter by status/severity, acknowledge / resolve / dismiss |
| **Tasks & Schedule** | Create, assign, complete, cancel; recurrence + priority; dashboard "due soon" widget |
| **Maintenance** | Full workflow: request → triage → assign → start → verify → complete (records history event) |
| **Spare Parts** | Inventory with low-stock markers, restock, spare-request lifecycle (approve → deliver → use) |
| **Documents** | Searchable machine documents; uploads feed the AI copilot's retrieval |
| **AI Copilot** | Floating chatbot on every page + full chat page: conversation history, tool calling, evidence chips, confirmed-action safety. Answers "temperature of X", "when will X turn off", "does X have any errors", "will X fail in weeks" and can design/generate your plant ("set up my plant: 2 extruders and 1 conveyor"). Works with NVIDIA NIM or offline fallback |
| **AI Insights** | Generated risk/anomaly insights with feedback loop |
| **Reports** | CSV / XLSX / PDF exports, all audited |
| **Notifications** | Per-user in-app notifications, unread badge, mark read |
| **Admin** | System health, users CRUD + role/status + password reset, audit log, AI usage/cost |
| **Profile** | Display name, password change, account info |

## No demo data mode (production-like)

The project never *requires* demo data. With `DEMO_MODE=false` and
`SEED_DEMO_DATA=false` in `.env` (and `data/smartplant.db` deleted) the system
starts **empty** — no users, no machines, no readings, no alerts:

1. The login screen shows **Create an account**. The first account becomes the
   plant **Administrator**; later accounts are Workers (promotable in Admin).
2. Add machines two ways: *Machines → Add machine*, or ask the AI Copilot —
   **"Set up my plant: 2 extruders and 1 conveyor"** — it designs the machines
   and you confirm.
3. Send real readings from **Telemetry → Ingest reading** (or the IoT gateway
   `POST /api/telemetry/ingest`). Alerts are generated by the alert engine,
   insights by the AI insight job, and every answer by the copilot — all from
   that live data.

Set `SIMULATE_TELEMETRY=false` so readings come only from real ingestion.

## AI — NVIDIA NIM (recommended)

Put your NVIDIA API key in `.env` (or the shell) and restart; that's all:

```bash
AI_MODE=auto
NVIDIA_API_KEY=nvapi-...                                # from build.nvidia.com
NVIDIA_BASE_URL=https://integrate.api.nvidia.com/v1
NVIDIA_MODEL=deepseek-ai/deepseek-v4-pro-0813
```

`NVIDIA_API_KEY` is the same environment variable the official NVIDIA SDK example
uses — set it once and the AI Copilot talks to `deepseek-ai/deepseek-v4-pro-0813`
on NIM with `temperature=1`, `top_p=0.95`, `seed=42`, `max_tokens=16384` and
thinking disabled for tool calling. `OPENAI_*` variables remain supported for any
other OpenAI-compatible endpoint (Ollama, vLLM, …). Without a key the deterministic
fallback engine runs — fully grounded, still passes the eval suite.
See [docs/AI.md](docs/AI.md).
